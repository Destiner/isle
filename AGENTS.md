# Isle

macOS menu-bar-less agent app. Tapping the fn / 🌐 key shows a Dynamic Island-style pill with a focused, minimal text field; the user types a message and presses **Enter** to send it to Codex (the `codex` CLI, reusing the user's ChatGPT login), and the answer shows in the pill. The pill walks through three phases — **ask** ("Ask", steady dot) → **thinking** (amber pulse) → **responding** ("Ready", no dot) — and stays open with the answer until the next turn; after an answer the field is focused again so the next question can be typed straight away. fn is a **toggle**: tapping it again while the pill is visible hides it (the conversation persists for the next open). The conversation **persists across turns**: each request replays the full history to Codex. Reopening **within** the idle window restores the last answer on screen (the pill comes back showing it, ready for a follow-up rather than blank). After the pill sits **closed for 5 minutes** the conversation is cleared — both the model-facing history and the on-screen answers — so the next open starts fresh.

**Input mode** (`IslandState.mode`, default `.text`) is switched live with **Tab** while the pill is open, and the last-used mode is remembered across launches (`UserDefaults`, key `inputMode`). A switch keeps the conversation (history + on-screen answer) but resets the in-progress compose, then hands off to the new mode's composer — voice starts recording, text grabs the field; Tab is ignored mid-thought (`AppDelegate.switchMode`). **Voice mode** (`.voice`): opening starts recording the mic, streaming recognized speech into the pill live (a two-line reverse-teleprompter); the whole loop is **hands-free** — once you stop talking the clip is transcribed locally (Parakeet) and sent (a silence endpoint in `DictationManager`), and once an answer is shown the mic stays quietly armed so simply speaking a follow-up flips back into listening (a speech-onset trigger; the answer stays readable until you actually talk). **Enter** still works as an instant override — submitting from listening, or starting the next turn from a shown answer. The voice model is lazy-loaded — at launch if the restored mode is voice, else on the first Tab into voice (`DictationManager.prepare()` is idempotent).

## Commands

- `xcodebuild -project Isle.xcodeproj -scheme Isle -configuration Debug -destination 'platform=macOS' build` - Build
- `xcodebuild test -project Isle.xcodeproj -scheme Isle -destination 'platform=macOS'` - Run tests
- `open $(xcodebuild -project Isle.xcodeproj -scheme Isle -configuration Debug -showBuildSettings | awk -F' = ' '/ BUILT_PRODUCTS_DIR /{d=$2}/ FULL_PRODUCT_NAME /{n=$2}END{print d"/"n}')` - Launch the built app
- `./install.sh` - Build **Debug** and install to `/Applications/Isle.app` (quitting any running copy). Local installs are always the Debug build on purpose: `Log` compiles only into Debug, so this is the version that writes session logs to `~/Library/Application Support/Isle/logs/`. There is no logging Release build — Release ships without it.

## Testing

- `IsleTests` holds fast unit tests (`CodexClient.CodexError.classify`); `IsleUITests` is still an empty Xcode stub. Run the unit tests with `-only-testing:IsleTests` (`xcodebuild test -project Isle.xcodeproj -scheme Isle -destination 'platform=macOS' -only-testing:IsleTests`) — the plain build already typechecks, and a bare `xcodebuild test` needlessly launches the app-driving UITests target.

## Stack

- Swift 5, SwiftUI + AppKit + AVFoundation + EventKit, deployment target macOS 26.3 (Apple Silicon)
- [FluidAudio](https://github.com/FluidInference/FluidAudio) (SPM) — Parakeet speech-to-text on CoreML / Neural Engine
- [swift-sdk](https://github.com/modelcontextprotocol/swift-sdk) `MCP` + [swift-nio](https://github.com/apple/swift-nio) (SPM) — host Isle's own MCP tool server in-process so Codex can call it (see `MCPServer.swift`)

## Structure

Source is grouped by responsibility under `Isle/Isle/` (`App/`, `UI/`, `Input/`, `Speech/`, `Agent/`, `Tools/`, `Diagnostics/`). New `.swift` files land in the matching folder and compile automatically (synchronized file groups — see Gotchas).

### App/

- `App/IsleApp.swift` - `@main` entry; no real scene (`Settings {}`), delegates to AppDelegate
- `App/Preferences.swift` - `InputMode` (`.voice`/`.text`) plus the `Preferences` struct: one place for every tunable knob (default mode, idle timeout, the `enableLogging` debug-log toggle, Codex `reasoningEffort`/`codexModel`/`systemPrompt`, the `computerAccess` sandbox toggle, the `codexTimeout` watchdog cap, the tool toggles (`enableReminderTools`/`enableCalendarTools`/`enableNotesTools`/`enableMailTools`/`enableBrowserTools`) plus browser knobs (`chromeHeadless`/`chromeDebuggingPort`), the two hands-free toggles `autoSubmitOnSilence`/`autoListenFollowUp`, and all endpointing thresholds). Today it's just compile-time defaults for personal use; it's the seam a future settings UI (or a `UserDefaults`-backed store) hangs off — the values flow one way, from a `Preferences` value into `AppDelegate` → `DictationManager` → `CodexClient`
- `App/AppDelegate.swift` - Lifecycle, panel placement, show/hide, layout constants, fn wiring, `switchMode()` (the Tab handler), mode persistence, and `submitTypedText()` (the text-mode send path). `show()` makes the panel **key** in both modes so it receives keystrokes (text needs the field's caret; voice needs Tab/Enter to reach the local monitor). Holds the idle timer (`armIdleTimer`/`cancelIdleTimer`): armed on `hide()`, cancelled on `show()`, it clears the whole conversation — the model-facing history (`dictation.clearHistory()`) and the on-screen answers (`state.reset()`) — once the pill has stayed closed past `preferences.idleTimeout` (5 min). `hide()` keeps the answers on screen (`state.prepareForClose()`, only the in-progress compose is dropped), so reopening before the timer fires takes the restore path: `onToggle` calls `state.restore()` when `state.hasHistory`, bringing the last answer back as the active turn (voice re-arms the follow-up mic via `armVoiceFollowUp`, text just refocuses the field). Owns the single `Preferences` value and injects it into `DictationManager`; the hands-free behaviors are gated on it — `armVoiceFollowUp` on `autoListenFollowUp`, the `onEndpoint` auto-submit on `autoSubmitOnSilence` (Enter still overrides when either is off).

### UI/

- `UI/PillPanel.swift` - Borderless non-activating floating `NSPanel`
- `UI/PillView.swift` - The pill UI: emerge/retract animation, the text-mode input field (`inputField`, a borderless `TextField` bound to `IslandState.draft`, focused via `@FocusState`/`syncFocus()`), the live transcript teleprompter (voice), the answer bubbles (`ResponseBubble`), the phase header (`StatusIndicator`), and `IslandState` (phase + transcript + `draft` + `mode` + staged reveal + `assistantTurns`)
- `UI/MarkdownText.swift` - Renders a Codex answer as styled markdown (headings, bold/italic, inline + fenced code, bullet/numbered lists, GFM pipe tables, blockquotes, rules). A small line-oriented block splitter (`MarkdownParser`) defers inline styling to `AttributedString(markdown:)`; no SPM dependency

### Input/

- `Input/FnKeyMonitor.swift` - Global fn-key tap detection (`onToggle`), a passive global `.keyDown` monitor for Enter (`onSubmit`, the click-away fallback), and a **local** `.keyDown` monitor for keys aimed at Isle while it holds focus: Tab → `onSwitchMode` (swallowed), Enter → `onSubmit` (passed through)

### Speech/

- `Speech/AudioRecorder.swift` - Mic capture, resampled to 16 kHz mono Float via `AVAudioConverter`; `snapshot()` reads the buffer mid-recording for live partials
- `Speech/DictationManager.swift` - Loads Parakeet (FluidAudio), re-transcribes the growing buffer on a timer for the live preview, and on Enter transcribes the full clip then hands it to `CodexClient`, surfacing the answer via callbacks (`onFinalTranscript` / `onResponse` / `onNoResponse`). `submitText(_:)` is the text-mode entry: it skips the mic/ASR and sends an already-composed message through the same history and callbacks. `cancelRecording()` stops the mic without sending when Isle is toggled off mid-listen. Owns the model-facing conversation `history` (cleared via `clearHistory()` when AppDelegate's idle timer fires)

### Agent/

- `Agent/CodexClient.swift` - Runs `codex exec` non-interactively via an interactive login shell (`zsh -ilc`) and returns the final assistant message. `send(_:history:effort:)` replays prior turns as a transcript so each one-shot run has full context, and a watchdog SIGKILLs the whole `zsh → node → codex` tree (children-first via `pgrep -P`, in `killProcessTree`) if the run outlasts `timeout`, surfacing `CodexError.timedOut` (see the codex-invocation pattern below). Codex's `--json` event log (stdout) is captured to a temp file and its tail folded into the error log on a failed/timed-out run; `pruneSessions` trims Codex's persisted session rollouts after a week. `ensureCodexHome()` points `CODEX_HOME` at an Isle-owned dir so Codex loads Isle's own `systemPrompt` (written to its `AGENTS.md`) instead of the user's personal `~/.codex/AGENTS.md`/`config.toml`; it also writes a `config.toml` with an `[mcp_servers.reminders]` `url` entry (from `mcpReminderURL`) so Codex can call Isle's reminder tools (model/effort still come from the `-c` flags, not this file)

### Tools/

- `Tools/RemindersService.swift` - EventKit-backed reminders access on its own `actor` (keeps the non-`Sendable` `EKEventStore` off the main thread): `list`/`search`/`get`/`create`/`edit`, each calling `ensureAccess()` (`requestFullAccessToReminders`) first and returning `ReminderDTO`s (never `EKReminder`, which isn't `Sendable`). Dates are ISO 8601 in/out
- `Tools/ReminderTools.swift` - The MCP tool surface: the five `Tool` declarations (JSON-Schema for `tools/list`) and `call(name:arguments:)`, which dispatches a `tools/call` to `RemindersService` and packages the result as a single JSON text block (errors become `isError` results with a readable message)
- `Tools/CalendarService.swift` - EventKit-backed calendar access on its own `actor`: `list_calendars` plus bounded `list_events`, `get_event`, `create_event`, and `edit_event`. It requests full event access on first use and returns `CalendarDTO`/`CalendarEventDTO`s, never `EKCalendar`/`EKEvent`; dates are ISO 8601 in/out. Edits to recurring events support this occurrence or all future occurrences; deletion is intentionally not exposed.
- `Tools/CalendarTools.swift` - The MCP calendar surface: the five calendar tool declarations and their JSON-Schema/dispatch, mirroring `ReminderTools`. Event creation is immediate; no confirmation layer exists.
- `Tools/NotesService.swift` - AppleScript-backed Apple Notes service on its own actor. It lists/searches/gets notes and folders, and creates, replaces, or appends notes; MCP receives plaintext while writes are converted to escaped HTML internally.
- `Tools/NotesTools.swift` - The seven Apple Notes MCP tools: `list_note_folders`/`list_notes`/`search_notes`/`get_note`/`create_note`/`edit_note`/`append_to_note`.
- `Tools/MailService.swift` - `EmailDTO`/`MailboxDTO`, the `MailProvider` protocol, `MailError`, and the `MailService` actor that forwards to the active provider. Mail.app is itself the multi-provider abstraction (it fronts Fastmail/Gmail/iCloud/etc.), so `AppleMailProvider` is the only backend today; the protocol is the seam a direct Gmail/JMAP client would slot behind later
- `Tools/AppleMailProvider.swift` - Drives Mail.app over AppleScript, in-process via `NSAppleScript` on a dedicated serial queue (in-process so the Apple Events TCC grant attributes to Isle, not a spawned `osascript` — same reasoning as the mic/Reminders grants). Read scripts return a US/RS-delimited (0x1F/0x1E control chars) string parsed back in Swift; `get`'s body is the final field so stray separators inside it survive the bounded split. `EmailDTO.id` is an opaque base64 of `{account, mailbox, numericId}` (Mail's own per-account numeric id isn't globally stable). `parseRow`/`literal` are `internal` (not `private`) so `IsleTests` can exercise them without a live Mail.app
- `Tools/MailTools.swift` - The MCP mail surface: seven `Tool` declarations (`search_emails`/`list_emails`/`get_email`/`send_email`/`create_draft`/`mark_read`/`list_mailboxes`) and `call(name:arguments:)` dispatching to `MailService`, mirroring `ReminderTools` (single JSON text block, `Log.tool` choke point, errors as `isError`). **`send_email` sends immediately — no confirmation step** (prototype-grade, same "misheard command runs with full access" caveat as the sandbox-off Codex path)
- `Tools/CDPClient.swift` - A minimal Chrome DevTools Protocol client over `URLSessionWebSocketTask` (no Node/Puppeteer, nothing bundled — it drives the user's own installed Chrome). CDP is JSON-RPC over WS: `send(method:params:)` correlates replies by integer `id` (each with its own timeout), ignores unsolicited events (the higher layer polls instead), and fails all in-flight commands on socket close. Returns raw `result` JSON as `Data` (Sendable) so it crosses cleanly into `BrowserService`'s actor
- `Tools/BrowserService.swift` - Actor that drives Chrome over CDP: `navigate`/`read`/`click`/`type`/`evaluate`/`screenshot` plus `show`/`hide`, returning `PageDTO`/`ScreenshotDTO`. Launches Chrome **lazily** on first use (it's heavy) against a **dedicated persistent profile** under Application Support (`chrome-profile`) with the debugging port open, so automation logins survive across runs without touching the user's everyday Chrome. Headless by default (`--headless=new`, which shares the same profile). `navigate` guards against silent no-ops (bad host → `errorText`; blocked top-level `data:` URLs → final URL unchanged). `show`/`hide` flip visibility — Chrome can't switch headless↔headed live, so they **relaunch against the same profile**, shutting the old one down **gracefully via CDP `Browser.close`** (SIGKILLing the process tree skips Chrome's cookie/localStorage flush and loses the session — a bug found the hard way)
- `Tools/BrowserTools.swift` - The MCP browser surface: seven `browser_*` `Tool` declarations (`navigate`/`read`/`click`/`type`/`evaluate`/`screenshot`/`show`/`hide` — `show`/`hide` are the human-in-the-loop escalation) and `call(name:arguments:)` dispatching to `BrowserService`, mirroring `ReminderTools`/`MailTools` (single JSON text block, `Log.tool` choke point, errors as `isError`)
- `Tools/MCPServer.swift` - `MCPHTTPServer`, a localhost Streamable-HTTP MCP endpoint hosted in-process. The `MCP` SDK's HTTP transport only maps `HTTPRequest`→`HTTPResponse`, so this wraps it in a small NIO HTTP/1.1 server (mirroring the SDK's conformance harness) — each Codex `initialize` opens a session with its own `StatefulHTTPServerTransport` + `Server`. One server fronts every provider: `makeServer()` merges `ReminderTools.tools` + `CalendarTools.tools` + `MailTools.tools` + `BrowserTools.tools` for `tools/list` and routes `tools/call` by name. Started (detached) from `AppDelegate`, gated on any enabled tool provider; any service may be `nil` when its pref is off. The NIO `MultiThreadedEventLoopGroup` runs a **pool** (`System.coreCount`), not one thread: Codex's streamable-HTTP client opens several connections during the handshake and treats any refusal as fatal (dropping *all* the server's tools), and long-lived SSE streams on a single loop starve the accept path — so a single-thread group intermittently failed the handshake

### Diagnostics/

- `Diagnostics/Log.swift` - `Log`, the single logging facade everything routes through (Codex runs, MCP tool calls, conversation turns, voice events, lifecycle). **Debug-only**: the whole path compiles to `false`/no-ops in Release (`#if DEBUG`) so nothing ships in a distributed build; in Debug it's on by default, and `Log.configure(enabled:)` (from `preferences.enableLogging`) or the `ISLE_LOG` env var (`0`/`1`, wins over the pref) flip it. Writes structured **JSONL** — one event per line with a shared envelope (`ts`, `level`, `cat`, `event`, plus `conv`+`turn` for conversation-scoped events) — and mirrors each line to `os_log` (subsystem `DestinerLabs.Isle`, category = `cat`). Holds the "current conversation/turn" context (the pill is single-turn, so it's global; lock-guarded because tool/codex events build lines off-main); `turnUser` lazily opens a conversation, `endConversation` (via `DictationManager.clearHistory` on idle-clear) closes it
- `Diagnostics/LogWriter.swift` - `LogWriter.shared`, the serial-queue file appender behind `Log`. Owns `~/Library/Application Support/Isle/logs/` and does every write on one private `DispatchQueue` (callers hand it finished lines, no locking of their own). Two targets: one always-open **`app.jsonl`** for app-scoped events, and **one `<stamp>-<id>.jsonl` per conversation** for turn/codex/tool/voice events (swapped on `beginConversation`). Nothing is rotated or deleted

## Patterns

- Background agent: `LSUIElement = YES` + `setActivationPolicy(.accessory)`, so no Dock icon or menu bar. Quit via right-click on the pill.
- The panel is intentionally taller than the pill (`topRoom`/`bottomRoom` in AppDelegate) so the animation can render outside the pill without being clipped by the window bounds.
- fn is a hardware modifier, not a key, so it's detected via `NSEvent` `.flagsChanged` keyed on `kVK_Function` — not a Carbon hotkey.
- Keyboard routing: the panel is a `.nonactivatingPanel` with `canBecomeKey = true`, so `makeKeyAndOrderFront` makes it **key** (caret + keystrokes) **without** activating Isle or defocusing the frontmost app (Raycast-style). It's now key in **both** modes (so Tab/Enter reach the local monitor) — the trade-off is that while a voice turn is open you can't type into the frontmost app. Two `.keyDown` monitors split the work by focus: the **local** one fires when Isle is key (the usual case while the pill is open) and handles Tab (switch, swallowed) and Enter; the **global** one fires only when another app is key — i.e. a voice turn where the user clicked away — so they never double-fire. In **text mode** Enter is handled by the field's own `.onSubmit` (`onSubmitText` → `submitTypedText`); the monitors' `onSubmit` is guarded on `mode == .voice`, so it's a no-op there and the local monitor passes Enter through to the field. Esc no longer dismisses; the panel's `cancelOperation` is a no-op that only swallows the default beep.
- Dictation uses Parakeet **v2** (English-only) via `AsrModels.downloadAndLoad(version: .v2)`; switch to `.v3` for multilingual.
- Endpointing: voice auto-submits on silence rather than waiting for Enter. `DictationManager` runs a cheap RMS gate (`AudioRecorder.trailingRMS`) on its own ~150 ms loop, decoupled from transcription latency: once speech has lasted `minSpeech` (0.4 s) and then the trailing `endpointWindow` (0.6 s) RMS stays below `silenceThreshold` (0.008) for `endpointSilence` (1.5 s), it fires `onEndpoint`, which AppDelegate wires to the same path as Enter-from-listening (gated on `autoSubmitOnSilence`). All these thresholds live in `Preferences`, not inline. The window is deliberately wide (0.6 s) so syllable-level gaps in speech don't read as silence — a short window plus a higher threshold caused false mid-speech submits. Thresholds are heuristic / hardware-dependent (tuned against a quiet built-in mic where speech RMS peaks ~0.02–0.03). This is energy-based, not a real VAD model.
- Hands-free follow-up (responding → listening): when an answer lands, `AppDelegate.armVoiceFollowUp` re-opens the mic with `startRecording(preview: false)` — only the RMS endpoint loop runs (no transcribing the reading-silence, which also avoids Parakeet hallucinating words onto it) while the pill still reads "Ready". The same loop fires `onSpeechStart` once `onsetSpeech` (0.2 s) of speech accumulates; AppDelegate then flips to listening (`startTurn`, which clears any stale transcript) and turns on the live preview (`enableLivePreview`). The mic keeps running across the flip, so the buffer — and the first words — are kept. Also re-armed after the error/empty fallbacks in `onNoResponse`.
- Live preview: the whole buffer is re-transcribed from scratch every ~350 ms (fresh decoder state) — clean text, no token-stitching. The preview is **append-only** (the shown prefix is frozen; the model's corrections to earlier words are dropped from the UI but still reach the final transcript sent to Codex). Words are revealed in **staged** steps so a line-fill and a new-line spill never share a frame, and the two-line viewport masks its top edge so the outgoing line dissolves instead of hard-clipping. `IslandState` and `TranscriptText` share `TranscriptMetrics` so the pacing and the rendered wrapping break lines at the same spots.
- Conversation as turns: each Codex answer is an `AssistantTurn` (stable id) in `IslandState.assistantTurns`. The last turn is "active" (white, full, scroll-capped) only while `phase == .responding`; otherwise it renders as a collapsed two-line greyed context bubble. Because the bubble keeps its identity across that flip, the active→context change **animates as a collapse** (both states share `ResponseBubble`; the measured height is animated in `onPreferenceChange` so it doesn't jump). The view shows the active turn plus one prior while responding, else just the single prior. The model-facing history (user + assistant text) lives separately in `DictationManager` and is replayed to Codex each turn — `codex exec` is one-shot, so context is carried by us, not a resumed session. The active answer renders as **markdown** (`MarkdownText`); the collapsed context line strips markdown to a flattened two-line plain-text preview (`ResponseBubble.plainPreview`) since structure isn't useful at two lines.
- `CodexClient` invokes `codex exec` through `zsh -ilc` (interactive **and** login) so the binary resolves on the user's PATH and reuses the terminal's ChatGPT login — no API keys. The interactive flag is load-bearing: `codex` lives in `~/.bun/bin`, which is added in `.zshrc` (interactive-only), so a plain `-lc` login shell can't find it when the app is launched from Finder/launchd. The prompt is piped on stdin and the final message read back from a temp file (`-o`), so neither needs shell escaping and prompt noise is ignored. It runs from an empty scratch dir with `model` and `model_reasoning_effort` passed as `-c` flags (from `preferences.codexModel`/`reasoningEffort`, effort default `low`) to keep spoken Q&A snappy, and `--json` so the event log is captured (see `CodexClient`). The sandbox flags are chosen by `preferences.computerAccess` (see the sandbox pattern below). `--ephemeral` is **not** passed — Codex persists a full per-run session rollout under `CODEX_HOME` (the authoritative trace of tool calls and shell commands, pruned after a week). Codex has no timeout when a response stream stalls (bytes stop with no close), so a run can hang forever; `CodexClient`'s watchdog caps it at `preferences.codexTimeout` (5 min) and kills the process tree.
- **Isolated `CODEX_HOME` (`ensureCodexHome`)**: by default `codex` loads the user's global `~/.codex/AGENTS.md` (their coding-agent dev instructions) on every run, which is wrong for spoken Q&A — and current Codex has no flag to replace the base instructions (`experimental_instructions_file` was removed; `--ignore-user-config`/`project_doc_max_bytes=0` don't suppress the global doc). So Isle points `CODEX_HOME` at `~/Library/Application Support/Isle/codex-home/`, writing its own `AGENTS.md` (from `preferences.systemPrompt`, rewritten each run as the source of truth). The ChatGPT login is shared by symlinking that home's `auth.json` back to the real `~/.codex/auth.json` (re-created each run if missing/clobbered — Codex rewrites `auth.json` only on a rare token refresh, via temp-file-then-rename, which would replace the symlink). Because the home is isolated, model is set explicitly (no inherited `config.toml`) and Isle gets its own fresh memories/goals/session state. **The sandbox is gated on `preferences.computerAccess`** (default **on**). When on, Codex runs `--dangerously-bypass-approvals-and-sandbox` so spoken requests can act on the machine ("open my Downloads", launch apps) — the trade-off is that a misheard command runs with full access **under Isle's TCC identity**, including sending Apple Events to any app (this is how a stray "control Music" prompt attributed to Isle, not just Mail). Under the default `-s read-only` sandbox those actions fail — file writes are "Operation not permitted" and `open` dies with `kLSExecutableIncorrectFormat` (Seatbelt blocks LaunchServices). When `computerAccess` is off, Codex runs `-s workspace-write -a never` instead: shell commands and scratch-dir writes still work, but Seatbelt blocks Apple Events to other apps and LaunchServices, so Codex can't drive arbitrary apps. Either way Isle's own Mail/Reminders MCP tools are unaffected — they run in-process in Isle, not as sandboxed Codex subprocesses. (`-a never` because Isle is non-interactive and can't answer approval prompts.)
- **Custom tools via MCP (`MCPServer.swift` + provider tool surfaces)**: Codex's only mechanism for model-callable tools is MCP servers (its "plugins/skills/hooks" are workflow extensions, not function tools). Isle hosts its own **in-process** Streamable-HTTP MCP server on `127.0.0.1:<mcpPort>` (default 8917) rather than a stdio helper Codex would spawn — two reasons: (1) EventKit then runs inside Isle, so the Reminders and Calendar TCC grants attribute to Isle's stable signed identity instead of a bare CLI (whose prompt attribution is unreliable, like the mic/Input-Monitoring cases below); (2) Isle is long-lived, so the server stays up across `codex exec` runs — no per-request process spawn. The MCP SDK's HTTP transport is framework-agnostic (`HTTPRequest`→`HTTPResponse` only), so `MCPServer.swift` supplies the listener via NIO, following the SDK's conformance harness (the reference impl that passes MCP conformance). The stateful transport's default pipeline is `AcceptHeaderValidator(mode: .sseRequired)`, so **responses are SSE** (`.stream`) — the NIO writer handles that case, not just plain JSON. `initialize` detection is inlined because the SDK's own classifier (`JSONRPCMessageKind`) is `package`-level and not visible to consumers. To add more tools, add a sibling provider and register it in `makeServer()`.
- **Browser automation (native CDP, nothing bundled)**: `BrowserService`/`BrowserTools` drive the user's **installed** Chrome by speaking CDP over a `URLSessionWebSocketTask` (`CDPClient`) — no Puppeteer, no Node, no bundled Chromium. Chrome is launched lazily against a dedicated `chrome-profile` (persistent logins, isolated from the user's everyday Chrome) and **headless by default**. The design point: run invisibly, and only surface a window when a human is actually needed — `browser_show` escalates to a visible window (login, CAPTCHA, confirm), `browser_hide` tucks it back. Since Chrome can't toggle headless↔headed live, both relaunch against the same on-disk profile and quit the old instance via CDP `Browser.close` (graceful, so cookies/localStorage flush — a `pkill` of the tree loses the session). The headless choice is an app pref, not a per-call tool arg: Chrome is launched once and reused, so it's a launch-time property, not something the model should babysit turn-to-turn.

## Gotchas

- **App Sandbox is disabled** (`ENABLE_APP_SANDBOX = NO`). Global keyboard monitoring requires it off; re-enabling breaks the fn trigger.
- The app needs **Accessibility permission** (global `.flagsChanged` for fn) and **Microphone permission** (dictation), plus **Input Monitoring permission** (global `.keyDown` for the Enter-to-submit monitor). Accessibility does **not** cover keystroke monitoring — `.flagsChanged` (fn) works under it but `.keyDown` (Enter) needs Input Monitoring, requested via `CGRequestListenEventAccess()`. The grant requires an app **relaunch** to take effect.
- **Hardened runtime requires the `com.apple.security.device.audio-input` entitlement** (`Isle/Isle.entitlements`) — without it macOS silently denies the mic and never shows a prompt.
- **Reminders** needs the `com.apple.security.personal-information.reminders` entitlement (same hardened-runtime reason as the mic) plus the `NSRemindersFullAccessUsageDescription` Info.plist key (set via `INFOPLIST_KEY_…` in build settings). First use prompts for Reminders access, attributed to Isle — launch from Finder/`open`, not a terminal, or the grant misattributes; the grant may need a relaunch.
- **Calendar** needs the `com.apple.security.personal-information.calendars` entitlement plus `NSCalendarsFullAccessUsageDescription`. Calendar tools call `requestFullAccessToEvents()` lazily, so the system prompt appears on their first use; use Finder/`open` for correct Isle attribution, and relaunch if macOS asks for it.
- **Mail (AppleScript)** needs the `com.apple.security.automation.apple-events` entitlement (hardened-runtime requirement to send Apple Events) plus the `NSAppleEventsUsageDescription` Info.plist key. First mail-tool use prompts "Isle wants to control Mail" (Automation) — same launch-from-Finder/relaunch caveats as Reminders. The prompt fires only on the first Apple Event, so it may surface mid-answer the first time Codex calls a mail tool.
- TCC ties permissions to the app's code identity (stable: signed `DestinerLabs.Isle`, team `HQR74263JL`), so a grant survives rebuilds. But launching the dev build _from a terminal_ can misattribute the permission prompt to the terminal — launch from Finder/`open` (e.g. a copy in `/Applications`) so prompts attribute to Isle.
- FluidAudio downloads its CoreML model (~450 MB) on first launch to `~/Library/Application Support/FluidAudio/Models/`; cached thereafter.
- The project uses synchronized file groups — new `.swift` files in `Isle/` are compiled automatically. **But** SPM dependencies still require manual `project.pbxproj` edits (no auto-sync for packages).
